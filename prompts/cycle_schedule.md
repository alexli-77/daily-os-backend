把这一期（双周）的要务排到具体的日子上。这是先于每日计划的一步：今天以后的每日计划，只从这份排期里取当天的那一片。

方法是柯维的「要事第一」：**不是给日程排优先级，而是给优先级排日程**。先把每个角色最重要的事（大石头）放进具体时段，再把其余的事分到日子上，最后剩下的空档才留给临时的事。

# 输入

Evidence 里的 `cycle_schedule_input`（`sources.cycle_schedule_input.data`）：

- `cycle`：这一期的 id、标签、第一天、最后一天。
- `today`：今天。**只排 `days` 里的日子**（今天到这一期最后一天），不要排过去的日子。
- `nowClock`：现在几点。今天的时段必须排在它之后；今天剩下的时间不够，就把事情排到后面的日子。
- `items`：这一期的要务。每条有：
  - `itemKey`：**必须原样回填**，不要改、不要编。
  - `text`：用户写的原文。
  - `role`：它所属的 OKR 目标。目标标题开头就是角色（工作 / 名利 / 自我 / 配偶 / 金钱 / 享乐 / 朋友……）。
  - `mit`：用户标了 MIT 的为 true。
- `days`：每一天的星期、工作日或休息日、工作时间、用餐时段、固定日程。
- `pastSessions`：今天之前已经排过的格子，只作参考，不要重排它们。

# 怎么排

1. **大石头先进日历。**
   - `mit: true` 的要务，以及每个角色里最重要的那一条，是大石头。
   - 大石头要给具体时段（`start`），并标 `"bigRock": true`。
   - 放在工作时间内，避开用餐和固定日程。
   - 尽量排在这一期的前半段，最晚在最后一天前 2 天做完，给意外留余地。
2. **按要务的性质决定排几次：**
   - 每天都要做的习惯（原文里有「每天」「每日」「日更」）：每个适用的日子排一次。时长按原文，例如「速写 1h」就是 60 分钟。不写 `start`。
   - 一次就能办完的事（买东西、办手续、贴签）：只排一次。要赶工作日办的，排在工作日。
   - 要做好几次的事（做作品集、写内容、做方案）：拆成几次，每次 45–120 分钟，分散在不同的日子里，不要挤在同一天。
   - 次数写在原文里的照原文排（「打球 3 次」「发布 2 篇」）。
3. **不是用户自己要做的事，不要排。** 比如「XX 日程」指的是别人安排好的活动，会出现在日历里，跳过它。
4. **控制每天的总量：**
   - 工作日：排进去的总时长不超过当天工作时间减去用餐和固定日程，再留 1 小时余量。
   - 休息日：只排享乐、朋友、配偶、自我这类角色的事；工作类的事除非原文写了截止日，否则不排。
5. **截止日：**
   - 原文写了日期的（例如「10.23 投递」），把那天放进 `deadlines`。
   - MIT 也给一个截止日，就是你计划做完它的那天。
   - 不确定的就不写。
6. 不要编要务，不要合并要务，也不要把一条要务拆成别的事。用户在这里只会看到要务原文和你排的日子。

# 输出格式（严格 JSON）

```
{
  "sessions": [
    { "itemKey": "a1b2c3d4", "date": "2026-10-08", "start": "10:00", "minutes": 120, "bigRock": true },
    { "itemKey": "e5f6a7b8", "date": "2026-10-08", "minutes": 60 }
  ],
  "deadlines": [
    { "itemKey": "a1b2c3d4", "date": "2026-10-09" }
  ],
  "note": "一句话说明这一期排期的关键取舍"
}
```

规则：

- 只输出这个 JSON 对象本身，不要加代码块，也不要加前后说明。
- `date` 用 `YYYY-MM-DD`，必须是 `days` 里的某一天。
- `minutes` 是 15 的倍数，15–240。
- `start` 用 `HH:mm`，只给大石头写。
- `note` 用中文，不超过 60 个字。
