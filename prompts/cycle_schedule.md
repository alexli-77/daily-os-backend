把这一期（双周）的要务排到具体的日子上。这是先于每日计划的一步：今天以后的每日计划，只从这份排期里取当天的那一片。

方法是柯维的「要事第一」：**不是给日程排优先级，而是给优先级排日程**。先把每个角色最重要的事（大石头）放进具体时段，再把其余的事分到日子上，最后剩下的空档才留给临时的事。

# 输入

Evidence 里的 `cycle_schedule_input`（`sources.cycle_schedule_input.data`）：

- `cycle`：这一期的 id、标签、第一天、最后一天。
- `today`：今天。**只排 `days` 里的日子**（今天到这一期最后一天），不要排过去的日子。
- `nowClock`：现在几点。今天的时段必须排在它之后；今天剩下的时间不够，就把事情排到后面的日子。
- `items`：这一期的要务。每条有：
  - `itemKey`：**必须原样回填**，不要改、不要编。
  - `text`：用户写的原文。
  - `role`：它所属的 OKR 目标。目标标题开头就是角色（工作 / 名利 / 自我 / 配偶 / 金钱 / 享乐 / 朋友……）。
  - `mit`：用户标了 MIT 的为 true。
- `days`：每一天的星期、工作日或休息日、工作时间、用餐时段、固定日程，以及 `events`——用户日历上那天已有的日程（会议、活动）。**`events` 占用的时段不能排任何东西**，大石头要排在它们之外。
- `pastSessions`：今天之前已经排过的格子，只作参考，不要重排它们。

# 怎么排

1. **大石头先进日历。**
   - `mit: true` 的要务，以及每个角色里最重要的那一条，是大石头。
   - 大石头要给具体时段（`start`），并标 `"bigRock": true`。
   - 放在工作时间内，避开用餐和固定日程。
   - 尽量排在这一期的前半段，最晚在最后一天前 2 天做完，给意外留余地。
2. **按要务的性质决定排几次：**
   - 每天都要做的习惯（原文里有「每天」「每日」「日更」）：每个适用的日子排一次。时长按原文，例如「速写 1h」就是 60 分钟。不写 `start`。
   - 一次就能办完的事（买东西、办手续、贴签）：只排一次。要赶工作日办的，排在工作日。
   - 要做好几次的事（做作品集、写内容、做方案）：拆成几次，每次 45–120 分钟，分散在不同的日子里，不要挤在同一天。
   - 次数写在原文里的照原文排（「打球 3 次」「发布 2 篇」）。
   - 当天有 `routine`（用户的作息）时：`fixed` 是作息里的固定块，什么都不能排；`routine.slots` 是按类别留出的时间格子。**每件事排进类别对应的格子**（作品集的事进作品集格子，英语进英语格子）；大石头的 `start` 落在格子里；一天里同类的事加起来不超过那个格子的时长。标了「保底」的格子对应的那件事，每个工作日都要排。
3. **不是用户自己要做的事，不要排。** 比如「XX 日程」指的是别人安排好的活动，会出现在日历里，跳过它。
4. **控制每天的总量：**
   - 工作日：排进去的总时长不超过当天工作时间减去用餐和固定日程，再留 1 小时余量。
   - 休息日：只排享乐、朋友、配偶、自我这类角色的事；工作类的事除非原文写了截止日，否则不排。
5. **截止日：**
   - 原文写了日期的（例如「10.23 投递」），把那天放进 `deadlines`。
   - MIT 也给一个截止日，就是你计划做完它的那天。
   - 不确定的就不写。
6. **每个格子写 `step`：这一次具体做什么**，一句话，动词开头，不超过 40 个字。
   - 一条要务排了好几次的，按先后拆成不同的步骤，几步合起来就是做完这条要务；不要每次都抄要务原文。例：「回捞用户」→ 第一次「整理回访表格，分析国内外用户」，第二次「海外发邮件引流进 Discord，国内企业微信群聊触达」。
   - 原文已经分了 1. 2. 3. 的，按原文的顺序分到各次。
   - 每天做的习惯，写当天的具体内容（练什么、画什么、读什么），没有线索就写朴素的「速写 1 小时」。
   - 步骤只能来自要务原文能推出的事，不要编新的项目、人、平台。
7. 不要编要务，也不要合并要务。用户在这里看到的是要务原文、你排的日子和每次的步骤。

# 输出格式（严格 JSON）

```
{
  "sessions": [
    { "itemKey": "a1b2c3d4", "date": "2026-10-08", "start": "10:00", "minutes": 120, "bigRock": true, "step": "整理回访表格，分析国内外用户" },
    { "itemKey": "a1b2c3d4", "date": "2026-10-09", "start": "10:00", "minutes": 90, "bigRock": true, "step": "海外发邮件引流进 Discord，国内企业微信触达" },
    { "itemKey": "e5f6a7b8", "date": "2026-10-08", "minutes": 60, "step": "速写 1 小时" }
  ],
  "deadlines": [
    { "itemKey": "a1b2c3d4", "date": "2026-10-09" }
  ],
  "note": "先守住「上线落地页」这块大石头：上午的工作格子留给它，临时的事排到下午"
}
```

规则：

- 只输出这个 JSON 对象本身，不要加代码块，也不要加前后说明。
- `date` 用 `YYYY-MM-DD`，必须是 `days` 里的某一天。
- `minutes` 是 15 的倍数，15–240。
- `start` 用 `HH:mm`，只给大石头写。
- `note` 是给用户的一句话指导，用柯维「要事第一、以终为始」的角度：点名这两周最该守住的那块大石头（具体到哪条要务），再说一个守住它的具体做法。
  - 对用户说话，用「你」或直接用祈使句；不复述排期里每天排了什么，不讲道理，不喊口号，不用破折号。
  - 中文，不超过 50 个字。
